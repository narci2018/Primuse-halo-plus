🎛️ 音乐源管理 rev -
这里增删改，App 里只读：客户端只保存这一个 URL，拉一次清单就拿到可用源、最新体检结论和该设备的界面文案。 体检判据是真出声：搜索命中 → 解析直链 → Range 取前 64KB → 校验音频字节魔数，只有"能访问"不算可用。 判为不可用的源会被自动停用并给出删除建议；runner_missing / no_sample / unsupported 这类"没法下结论"的情况不会停用任何源。
这个令牌是什么：服务端写接口的唯一凭证。 清单读取是开放的（App 也走它，所以不需要令牌）；但增删改源、启停、体检、改首页文案、动样本池这些 写操作一律要 Authorization: Bearer <令牌> —— 这个后台是 CORS: * 的公网页面， 没有它任何人都能改音源、把全站用户的播放带偏。没配令牌时写接口直接 503（fail closed），不会退化成"谁都能改"。
去哪拿：Cloudflare 控制台 → Pages → 本项目 → Settings → Environment variables → 变量 SOURCES_ADMIN_TOKEN。 那里只存不回显明文；本机仓库的 .deploy-secrets.txt（已 gitignore）留有明文，忘了就从那里取，或重新设一个再 wrangler pages secret put。 另有低权限的 SOURCES_CHECK_TOKEN，只够调 check-one / check-plan，适合给"只想让它体检别想改源"的人。
「记住令牌」做什么：把它写进本标签页的 sessionStorage，之后每次点写操作自动带上，省去反复粘贴。 它不落 localStorage、不进磁盘、关闭标签页即消失，刷新页面就要重填 —— 令牌泄漏的窗口只有一次会话那么长。

🧪 体检样本池（probe_samples_v1）
体检要"真出声"就得先有一首真实的歌去解析取流。会搜索的线路每次命中都会把歌曲 id 攒进这里（每平台上限 24 个）， 洛雪 js 音源不会搜索，就靠这份池子被体检。某个平台的池子是空的、而这个平台的源又没有一个会搜 —— 服务端就只能报未检出（no_sample）：这不是"源坏了"，是我们手上没它的考题，所以既不停用也不加载进 App。 填一个该平台的真实歌曲 id（网易云 / QQ / 酷狗 / 酷我 / 咪咕的歌单页地址里那串数字），再对那条源点"用歌曲 id 复测"， 结论就从"未检出"变成真的能播或不能播。

📋 复制歌单到其他设备

⚠️ 注意：复制操作会将源设备的所有歌单完全覆盖写入到目标设备。若目标设备已有歌单，原歌单将被替换。

🔀 合并歌单到目标设备

💡 智能合并规则：
1. 若两台设备存在同名歌单，歌曲将自动按歌曲 ID 去重并合并，不会重复添加同一首歌。
2. 若目标设备中不存在源设备的某歌单，该歌单将自动追加至目标设备。
3. 目标设备原有的其他歌单将完全保留，不会丢失。

🧩 洛雪音源执行体（runner Worker）

Cloudflare 边缘禁止在请求里生成代码，所以 js 音源只能在部署期就写死进 bundle 的 runner Worker 里跑： 脚本正文作为 Text 模块进包（混淆稿一旦被打包器解析就整包发布失败），启动阶段再交给 new Function 编成沙箱 —— 和洛雪官方执行音源的方式一致。 音源有增删改后点「重新部署」把当前启用的脚本集推上去；缺 CF 凭据时会明确报「未部署」，不会假装成功。
